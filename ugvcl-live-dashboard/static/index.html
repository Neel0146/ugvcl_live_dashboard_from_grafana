How each number is calculated
  • Total meters: devices with serial number starting "U" that are not templates (SQL Server device master, per CLR).
  • Expected: measuring points of that profile on those devices (midnight, billing, load profile, instant result types for the CLR).
  • Received: distinct measuring points with a reading today (billing: this month's reading) in the Postgres result tables result_24h_double, result_1month_double, result_30m_double, result_0s_double. Same logic as the "All data summary today (MPRT)" dashboard.
  • Percent = received / expected, capped at 100. If received is above expected the tile is flagged.
  • "Today" follows the database server's date, exactly as in the Grafana dashboards. A past date counts measuring points whose reading is stamped on that date (billing: that month).
  • Total adds the four CLRs. A percentage total is total received divided by total expected, not an average of the four percentages. If a CLR has no data the total says how many CLRs it covers.
  • Communication type, metering mode and the attribute explorer show the current device master, not a past date.
